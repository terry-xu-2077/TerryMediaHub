更新日期：2026-11-04（Asia/Shanghai）。状态：需求与架构设计，尚未实施新服务。

本文是需求与范围的主文档。配套阅读：[代码架构补充](architecture.md)、[验收清单](acceptance.md)、[兼容性与现状](compatibility.md)。当前交付仅包含文档，后文的代码目录、接口及部署方式均为目标设计。

## 一、项目目标与范围

构建部署在本机 Windows 上的独立家庭媒体服务器，将影视仓订阅源与本地视频整合为漂亮的媒体库，提供浏览器和独立电视应用。

参考 Jellyfin 的浏览、选集、续播和播放决策机制；视觉采用 Apple TV / Infuse 风格。**默认原码播放，转码作为兼容性兜底。**

| 项目 | 确定方案 |
|---|---|
| 服务端 | Go，独立运行，不依赖 Jellyfin |
| 数据库 | SQLite |
| Web | React＋TypeScript＋Vite |
| 电视端 | Kotlin＋Compose for TV＋Media3/ExoPlayer |
| 部署 | 当前 Windows 电脑，家庭局域网 |
| 目标电视 | 小米 HyperOS 3.0.102.0，具体 Android 版本与解码能力实机识别 |
| 内容 | 在线点播＋本地视频 |
| 内容组织 | 近期热播、搜索、收藏、追剧、继续观看 |
| 首版源能力 | CMS、JAR、JS、Python |
| 首个订阅 | 现有盒子迷配置 |
| 用户 | 一个管理员，多个家庭档案 |
| 元数据 | 源资料优先，TMDB 可选补全 |
| 弹幕 | 源弹幕优先，弹弹play 可选，支持文件导入 |

本机已有流畅运行 Jellyfin 的实际经验，不因硬件参数预先削减功能或画质。低开销通过增量更新、按需启动运行时、缓存及避免不必要转码实现。

首版暂不包含直播/EPG、网盘账号登录、磁力/P2P、自动浏览器嗅探、投屏协议和公网部署。

## 二、产品功能与交互

### 媒体库

- 首页：精选推荐、继续观看、近期热播、追剧更新、最近加入、收藏。
- 热播使用源实际提供的推荐或榜单；只有更新时间时显示“近期更新”。
- 搜索同时覆盖本地文件、缓存条目和启用的在线站点，结果逐步呈现，慢站不阻塞整体。
- 推荐只同步有限列表，详情与播放地址按需获取；收藏、追剧和观看记录长期保存。
- 同一作品的本地文件与在线线路聚合到详情页，保留站点、版本、清晰度及语言区别。
- 可靠外部 ID 优先用于归并；名称、年份、类型辅助匹配。不能确定时保持独立，管理员可手动合并、拆分和匹配。
- 源失效不删除收藏和历史，可重新寻找资源。

### 本地媒体

支持添加多个本机目录，通过首次扫描、目录变更检测与定期校验维护索引。

读取视频、字幕、NFO、海报和背景图；可选 TMDB 补全。扫描默认只读，不移动、重命名、删除视频或回写媒体目录。

区分电影、剧集、季和单集。无法识别的文件进入待整理列表，支持人工匹配。

### 播放与家庭档案

首版支持续播、自动下一集、倍速、音轨字幕、字幕偏移、手动换线、失败自动换线，以及按剧配置片头片尾跳过并允许单集覆盖。

自动换线必须确认对应同一单集。不同剪辑版或明显不同的时长需要提示，不承诺跨版本无缝续播。

家庭档案分别保存收藏、追剧、观看进度及偏好。电视通过网页批准的配对码加入，管理员操作单独鉴权。

弹幕支持匹配纠正、时间偏移、字号、透明度、密度、区域及关键词过滤。客户端绘制弹幕，不烧录视频；弹幕失败不影响播放。首版不发送弹幕。

### 视觉与电视操作

- 深色主界面、大海报、宽幅背景、干净排版和适量动效。
- 首页不自动播放预告片。
- 详情突出播放、续播、选集和收藏，线路管理放在次级面板。
- 手机、电脑和电视共享视觉规范，各自采用适合设备的布局。
- 电视所有核心操作可用方向键、确认和返回完成；返回恢复焦点和滚动位置。
- 为缺图、空库、加载、断网和源失效设计完整状态。

## 三、代码架构

### 3.1 总体结构

采用**模块化单体服务＋独立解析进程＋原生客户端**。

Go 主服务统一处理数据库、用户状态、媒体库、播放会话和任务调度。解析脚本与 FFmpeg 运行在独立进程中，分别管理生命周期。

```text
浏览器 Web                         小米电视 APK
React / HTML5 Video               Compose / Media3
          │                            │
          └──── REST API / SSE ────────┘
                         │
                 Go 主服务
       ┌─────────────────┼─────────────────┐
       │                 │                 │
   媒体库与搜索       播放与流代理       用户与管理
       │                 │                 │
       ├──── SQLite / 图片缓存 / 任务队列 ──┤
       │                 │
   解析进程管理器     FFprobe / FFmpeg
       │
       ├── JVM：JAR / CSP
       ├── Node.js：JS / drpy 适配
       └── CPython：Python Spider
```

主服务不要求 Redis、独立数据库服务器或常驻 Node Web 服务。Web 编译成静态资源，随 Go 服务发布。

### 3.3 服务端依赖与模块边界

依赖方向固定：

```text
HTTP 接口 → Application 用例 → Domain 规则
                    ↓
                  Ports
                    ↑
        SQLite / Worker / FFmpeg 等实现
```

- `domain` 不依赖 HTTP、SQLite、FFmpeg 或运行时进程。
- `application` 组织业务流程，通过接口访问外部能力。
- `adapters` 实现接口，不反向承载核心业务规则。
- `bootstrap` 是唯一集中装配依赖的入口，不使用遍布项目的全局单例。
- HTTP Handler 只处理请求校验、身份上下文、用例调用和响应转换，不直接执行 SQL 或拼装 FFmpeg 参数。
- 数据库事务在应用用例边界发起，远程抓取和转码不占用长事务。

| 模块 | 负责内容 |
|---|---|
| Library | 扫描、本地索引、作品归并、版本关系、人工匹配 |
| Discovery | 推荐更新、聚合搜索、结果去重和渐进返回 |
| Sources | 订阅、站点能力、解析调度、健康状态 |
| Playback | 播放决策、会话、换线、重试和进度 |
| Streaming | 原码转发、Range、HLS 重写及输出 |
| Danmaku | 匹配、加载、缓存、标准化 |
| Household | 管理员、档案、设备、收藏和追剧 |
| Jobs | 扫描、刷新、清理任务及进度 |
| FFmpeg | 媒体探测、受控参数生成、转码执行和清理 |

播放决策使用独立、可测试的策略模块；FFmpeg 执行模块只执行明确的媒体处理计划，不自行决定是否降低画质。

### 3.4 核心数据模型

内容身份与播放资源分开建模：

| 模型 | 用途 |
|---|---|
| Media / Season / Episode | 作品、季和单集身份 |
| MediaVersion | 剪辑版、清晰度、语言等版本差异 |
| SourceEntry / PlaybackRoute | 源站条目及其播放线路 |
| LocalAsset | 本地文件、字幕及探测结果 |
| Subscription / Site | 订阅配置、站点身份及所属运行时 |
| Profile / Device | 家庭档案与已配对设备 |
| Favorite / Follow / WatchProgress | 收藏、追剧与观看状态 |
| PlaybackSession | 播放方式、资源、进度和生命周期 |
| DanmakuBinding | 单集与弹幕数据的匹配关系 |
| Job | 后台任务状态、进度及错误摘要 |

内部稳定 ID 不使用播放 URL。临时直链与 Cookie 具有独立生命周期，过期后重新解析，不改变作品或观看记录的身份。

每个站点使用“订阅归属＋站点标识”定位，避免不同订阅之间串用 JAR、配置及状态。

### 3.5 解析运行时架构

CMS 在 Go 内原生解析；JAR、JS、Python 通过独立 worker 接入。

统一源接口包含：

```text
Capabilities
Home
Categories
List
Search
Detail
ResolvePlayback
Proxy
```

worker 控制通道使用带版本号的逐行 JSON RPC，包含请求 ID、操作、站点上下文、参数、截止时间和结构化错误。标准输出只传协议，日志写标准错误。

需要持续搬运二进制数据的源内代理，通过仅监听回环地址、带临时凭据的 HTTP 通道完成；不把视频内容编码后塞进 JSON RPC。

关键约束：

- 全局 JAR、站点 JAR、脚本、扩展配置与依赖按所属订阅管理。
- JS 适配器区分 drpy 与其他脚本协议，补齐其宿主能力。
- Python 适配器实现实际 Spider 接口和依赖加载。
- 同一 worker 内存在全局状态的调用串行执行，通过独立实例隔离站点。
- 播放解析优先于后台刷新；超时可终止对应 worker 并恢复。
- 运行时版本固定，源脚本按内容哈希缓存，保留最近可用版本。
- 进程隔离用于故障恢复，不能将其当作安全沙箱；worker 使用受限权限和独立工作目录，不继承管理凭据。

现有 `SpiderHost.jar` 可作为验证与迁移参考，但正式交付需要具备可维护源码、依赖说明和可复现构建。

### 3.6 客户端架构与 API 契约

Web 按业务功能组织，各功能包含页面、组件、查询和状态；播放器单独封装，页面不直接操纵 HLS 内部对象。

电视采用单向状态流：界面发送操作，ViewModel 调用用例或仓储，StateFlow 输出界面状态。播放器由独立会话控制器管理，弹幕作为覆盖层绘制。

两端共享 API 语义、错误码、播放状态及视觉规范，各自实现布局与交互，不强行共享 UI 代码。

接口使用 `/api/v1`：

| 接口分组 | 能力 |
|---|---|
| `/auth`、`/devices`、`/profiles` | 初始化、登录、配对、档案 |
| `/home`、`/search` | 首页与聚合搜索 |
| `/media` | 详情、季集、版本和资源 |
| `/favorites`、`/follows`、`/progress` | 个人状态 |
| `/subscriptions`、`/sites` | 源配置及能力 |
| `/libraries`、`/jobs` | 本地目录、扫描与任务 |
| `/playback/sessions` | 创建会话、心跳、错误及停止 |
| `/streams` | 会话授权的媒体输出 |
| `/danmaku` | 匹配、导入、加载及偏移 |
| `/events` | SSE 搜索结果与任务进度 |

OpenAPI 为公共 API 的单一契约来源，生成 TypeScript/Kotlin 客户端模型。worker 协议单独版本化，不暴露给前端。

创建播放会话提交资源选择、起播时间和客户端能力；返回会话 ID、播放地址、模式、音轨字幕和降级原因。文件路径、订阅密钥及源 Cookie 不进入公共响应。

## 四、播放、数据和运行策略

### 播放决策

```text
作品/单集
  → 选择本地版本或在线线路
  → 解析真实资源
  → 比对媒体信息和客户端能力
  → 原码直连 / 原码代理 / 换封装 / 音频转码 / 视频转码
  → 会话上报与跨设备续播
```

| 播放方式 | 处理原则 |
|---|---|
| 原码直连 | 客户端可解码且可直接取流时使用 |
| 原码代理 | 解决请求头、Cookie、同源和网络访问问题，不重编码 |
| 换封装 | 编码兼容但容器不兼容时复制音视频流 |
| 音频转码 | 视频兼容时保留原视频 |
| 视频转码 | 视频解码、字幕烧录或用户选择确实需要时启用 |

采用 [jellyfin-ffmpeg](https://github.com/jellyfin/jellyfin-ffmpeg)，参考 [Jellyfin 的播放分层策略](https://jellyfin.org/docs/general/post-install/transcoding/)。

默认不降低能够直通内容的分辨率、码率或 HDR。转码使用经实测可用的硬件能力，软件处理作为必要兜底。

403、地址过期、网络超时和源失效优先刷新资源或换线，不直接触发转码。重试有上限，错误保留可诊断原因。

代理覆盖 Range、HLS 主子列表、分片、密钥与初始化片段。转码支持拖动重建、断开取消、进程树回收及临时文件清理。

### 数据与后台任务

- SQLite 启用 WAL，采用短事务与集中写入调度，避免并发刷新造成长锁。
- 默认每 12 小时刷新订阅与有限推荐；手动刷新和增量更新共用同一任务入口。
- 搜索结果短期缓存；收藏、追剧和历史持久保存。
- 图片、元数据、脚本、探测结果与转码文件分别管理缓存和过期策略。
- 不为原码代理缓存整部影片，也不预先转码整库。
- 后台任务支持取消、进度查询和重启恢复，避免重复全量执行。
- 日志关联请求、任务、站点及播放会话，敏感请求头和凭据脱敏。

### Windows 部署

提供原生运行包与 Windows 服务模式，数据目录默认使用 `%ProgramData%\TerryMediaHub`，与程序安装目录分离。

Go 服务随包提供 Web 静态文件；解析运行时和 FFmpeg 版本固定、独立存放。首次初始化从本机完成，随后启用已认证的局域网设备。

升级前备份 SQLite 与配置；迁移按版本执行。回退涉及数据库结构变化时，使用与旧版本匹配的备份恢复。

## 五、实施顺序与验收

### 实施阶段

1. **兼容性与架构基线**
   保存盒子迷配置样本，确定四类源的验收站点；恢复 JVM 宿主构建；建立 OpenAPI、worker 协议、数据库迁移及项目骨架。

2. **服务与播放闭环**
   实现订阅、四类解析器、搜索、多线路、本地扫描、媒体归并和五级播放策略。

3. **Web 完整体验**
   完成首页、海报墙、详情、播放、家庭档案、收藏追剧与弹幕。

4. **电视完整体验**
   完成 APK、设备配对、遥控焦点、原生播放、弹幕及跨设备续播。

5. **本机交付**
   完成安装包、服务管理、备份恢复、诊断文档和实际设备验收。

四类源、Web 与电视端均属于首版完成条件。

### 测试与验收

- **领域测试**：作品归并、集数匹配、线路选择、播放决策及错误分类。
- **协议测试**：OpenAPI 与客户端一致；worker 正常返回、乱序、超时、崩溃及取消。
- **源测试**：四类源每类至少两个当时可用的常规点播站点，验证搜索、详情、选集、解析和实际播放。
- **流媒体测试**：Range、HLS 相对地址、密钥、初始化片段、请求头、过期 URL 与跳转。
- **播放测试**：覆盖 MP4/MKV、HLS、H.264/HEVC、常见音频、多音轨、外挂字幕与可用 HDR 样本。
- **状态测试**：多个档案不串数据，跨设备续播正确；源删除或目录离线保留历史。
- **降级测试**：TMDB、弹幕或单个 worker 故障不影响其他播放。
- **生命周期测试**：停止、拖动、断连、服务重启后无残留 FFmpeg/worker 或失控缓存。
- **实机测试**：小米电视仅用遥控器完成全部核心操作，开启弹幕后仍流畅。

性能在相同机器、媒体和客户端条件下与现有 Jellyfin 对照，记录首帧、拖动恢复、CPU、内存和磁盘写入。可直通样本不得重编码，换封装不得重编码视频。

在本地或可控测试源上连续播放两小时，并验证两路同时播放时浏览、搜索和后台更新仍正常响应。
